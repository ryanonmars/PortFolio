# PortFolio v0.4.1

v0.4.1 brings full-page Settings and complete browser backup/restore to the published application. The board editor and v0.4.0 MCP/integration features remain available.

## New

- **Full-page Settings:** General, Backup & Restore, API Tokens, and About open in the main application area while the board browser stays available.
- **Complete backup downloads:** Download a portable ZIP containing the SQLite snapshot, boards, attachments, account records, and integration state through an authenticated browser session.
- **Reviewed browser restore:** Upload a complete ZIP, review verified metadata and counts, type `RESTORE`, and confirm before replacing persistent application state. Normal activation requires no Docker or process restart.
- **Recovery before replacement:** Each confirmed restore creates and verifies a recovery ZIP first. The latest three verified recovery ZIPs remain available for authenticated download.
- **Running version information:** About reports the actual application version, database migration version, and Node runtime from the server.
- **Single-instance protection:** A lifetime SQLite lease prevents a second PortFolio server from sharing the same `DATA_DIR`.

## Backup and restore details

Complete ZIP backups are unencrypted and contain sensitive private documentation, account password hashes, and API token digests. Save independent off-server copies and protect access. Runtime environment variables, `.env`, logs, caches, and existing backups are excluded; deployment configuration stays with the current installation.

Restore previews expire after 15 minutes. The default archive and expanded-data limit is 4 GiB. Verification checks the manifest, file hashes, database integrity and migration compatibility, board documents, and attachment references before activation. Allow enough free space for staging, the prepared restore, a verified recovery backup, and the old state during activation.

A successful restore invalidates browser sessions. Sign in with an account/password from the backup. API tokens return to their saved expiration/revocation state; review access after recovery.

The advanced CLI snapshot-plus-attachments format remains supported for scripted backup/recovery into a new empty directory. Existing CLI backup pairs are not browser ZIP uploads. Board JSON import/export is also separate and does not include attachment binaries.

See the [backup and restore guide](https://github.com/ryanonmars/PortFolio/blob/v0.4.1/docs/BACKUP_RESTORE.md) for recovery procedures and operational limits.

## Update

Create a complete backup before updating. On v0.4.0, use the existing CLI backup command and retain both the SQLite snapshot and its adjacent attachment directory. Change the deployment's `IMAGE_TAG` to `v0.4.1`, then run:

```sh
docker compose pull
docker compose up -d --wait
```

No SQL migration is introduced in v0.4.1. Existing board, attachment, and integration records are retained. Keep the persistent `/data` mount and its configured UID/GID access. After upgrading, open Settings and download a complete browser ZIP for future browser restoration.

See the [installation guide](https://github.com/ryanonmars/PortFolio/blob/v0.4.1/docs/INSTALLATION.md) for source installations, private networking, and advanced CLI recovery.
